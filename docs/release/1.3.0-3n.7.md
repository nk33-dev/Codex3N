## 安全加固

- 本地 helper（监听 `127.0.0.1`、没有入站鉴权、会用保存的 Key 代发上游请求）新增请求边界：对端必须是回环地址，来源必须落在可注入页面白名单（本地 `app://-` 主界面与 ChatGPT 桌面页），并按来源回显 `Access-Control-Allow-Origin`，不再下发通配符。任意网页来源与不透明来源（`null`，沙箱 iframe / `file://` / `data:` 都会被序列化成它）默认拒绝。两个默认关闭的逃生开关与诊断关键字见 `doc/person/runtime.md`。
- 设置文件里的 API Key 改为**落盘加密**（AES-256-GCM，主密钥由 Windows DPAPI / macOS 钥匙串保护），内存中仍是明文，界面与调用方行为不变。老格式明文可正常读回，并在下次保存时自动升级为密文，不需要迁移命令。凭据库不可用时保存回落明文并写一次诊断日志；解密失败不改写磁盘、不影响其余设置。
- 自更新链新增两道默认**失败关闭**的闸门：安装包必须通过 sha256 校验（发布侧新增 `SHA256SUMS.txt`，并写进 `latest.json` 的 asset 元数据），且目标版本必须高于当前版本。校验失败会删除已下载文件，绝不启动安装包。两个逃生开关见 `doc/person/runtime.md`。
- 插件市场解锁补丁现在可以真正还原：`clearPluginPatchArtifacts()` 会还原四处宿主对象，原始方法与绑定副本分开保存，避免关闭功能后仍留补丁。

## 修复

- 修复发往环回地址的请求被本机代理接管的问题：Windows `ProxyOverride` 里的 `127.*` 在上游 hyper-util 中解析失效（`*.` 被替换掉后只剩 `127.`，不是有效条目；而 IP 字面量只查 IP 表），于是 `127.0.0.1` 请求会被交给系统代理；代理把请求转交给远端节点后，远端连的是它自己的 `127.0.0.1:<端口>`，连接被拒就返回 502。环回目标现在改用**显式禁用代理匹配**的客户端（reqwest `auto_sys_proxy = false`），系统代理与 `HTTP_PROXY`/`HTTPS_PROXY`/`ALL_PROXY` 环境变量都不再作用于环回；**非环回目标行为完全不变**。本地 relay、把协议代理当供应商、本地 VLM 与模型目录探测等配置不再偶发 502。
- 修复三条受系统代理影响的测试（`protocol_proxy`、`vision`、`model_catalog`），以及 `protocol_proxy` 里测试锁被 panic 污染后连累其余十几个用例报错的级联。
- 测试门禁与发布脚本加 `--no-fail-fast`：一条失败不再掩盖其余测试目标的结果。
